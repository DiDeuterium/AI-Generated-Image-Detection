# AI 生成图像检测 · 验证与测试偏移调查

## 结论

**验证集和测试集存在可验证的类条件偏移。** 固定的 80/20 验证保留了原训练数据的编码和尺寸规律。已提交的 C 模型在原图验证为 92.31%，仅 q75 代理为 91.50%，只缩放到 0.75 倍便降到 72.94%，强退化代理为 63.94%，该提交的比赛分数为 0.560。只做 JPEG 重编码会漏掉最重要的脆弱点。代理图仍来自训练来源体系，因此这些数值衡量的是对受控退化的鲁棒性。真实测试的来源、生成器和逐图真值待主办方确认。

## 图像全量审计

所有格式均以 Pillow 读取的文件头为准。训练与验证各组的编码规律完全一致。

| 组别 | 实际编码 | 正方形 | 短边中位数 | 原图中央区域 Laplacian 均值 |
| --- | --- | ---: | ---: | ---: |
| 全部标注真图 4,000 | JPEG 4,000 | 125 | 375 | 0.10585 |
| 全部标注生成图 4,000 | PNG 4,000 | 4,000 | 384 | 0.07049 |
| 测试图 1,000 | JPEG 965，PNG 30，WEBP 5 | 82 | 500 | 0.05291 |

Laplacian 为灰度 `[0,1]` 中央最多 `320×320` 像素区域的绝对四邻域差分均值，按原尺度计算。测试是无标签的混合分布，整体更平滑无法揭示哪一类更多。训练生成图固定为 128、256、512 或 1,024 像素正方形。标注真图有 1,286 种尺寸，其中 2,768 张有一边为 500 像素。测试有 235 种尺寸，长边中位数 681.5 像素，高于标注真图的 500 像素。测试还明显集中于 `500×333`（160）、`500×750`（95）、`764×1146`（66）和 `450×675`（49）。

测试的 965 个 JPEG 有 964 个被 Pillow 识别为 4:2:0，1 个返回未识别。对 965 张 JPEG 按完整量化表分组，可见两个主要处理批次：

- **500 张宽度恰为 500 的 JPEG** 全部共享同一组量化表。其亮度表与 Pillow q75 相同，色度表 64 项里有 1 项不同。测试中没有其他宽 500 的图。500 张均无非空 EXIF 或 ICC。原始标注真图中宽 500 的 2,088 张里有 19 张含 EXIF、675 张含 ICC，并多为 q96/4:4:4。
- **460 张其余宽度的 JPEG** 完整量化表与 Pillow q75 相同。其余 40 张由 5 张其他 JPEG、30 张 PNG 和 5 张 WEBP 构成。
- 两组在 ID 中交错分布。旧提交给宽 500 组判生成 **35/500**，给其余组判生成 **95/500**。这说明模型输出与处理批次相关。假设宽 500 组全真、其他组全生成，该假设与旧提交恰好一致 560 行，也与后续候选恰好一致 538 行。两者分别等于用户报告的 0.560 和 0.538。第二份候选在看到比赛分数前已由验证像素分数确定，使这个巧合成为更强的构造线索。两次聚合评分仍允许其他真值向量。例如在两个批次中交换一对被两份提交都判同类的样本的假设标签，会保持两份总分。批次与来源的对应需要主办方确认。测试候选的分类只用模型像素分数。

全量比对了 **1,000×8,000 个测试对标注图像对**及 **1,600×6,400 个验证对训练图像对**。SHA-256 文件字节无匹配，63 位 pHash 与 64 位 dHash 无同时精确匹配，在 pHash≤8 且 dHash≤10 的联合门槛下也均为零。测试最小联合距离为 21，验证最小为 24。该检查能排除所测阈值下的简单感知近重复。大幅裁剪、构图变化或同一生成器产出仍可能绕过这些哈希。

## 旧提交与类别先验

旧提交与比赛模板的 1,000 个 ID 顺序、唯一性及覆盖一致，代码将 `prob[:,1]` 视为生成类，训练标签和目录一致。旧提交有 130 张标 1，旧概率文件按 0.5 切分有 129 张标 1，唯一差异是 `image_0655.jpg`，概率 0.492363，旧提交标 1。这个单点差异解释不了验证与测试的差距。比赛评测页面未能从本环境独立读取，下述代数按交接所述全量 Accuracy 定义成立。

设测试真实生成图数为 F，旧提交的正确生成预测数为 TP。由 0.560 得 `870 − F + 2 TP = 560`，因此 `F = 310 + 2 TP`。所以 **F 在 310–570**，TP 可在 0–130，生成召回可在 0–22.8%。这也严格推出测试至少 **275 张生成图为 JPEG、228 张生成图为非正方形**，即使完全不知道逐图标签，编码和几何的类条件分布也发生了变化。标签全反的分数为 `1 − 0.560 = 0.440`，无需占用 Kaggle 名额。

旧 CAP 特征用 6,400 张训练图建立四种特征库，每张图拼接四路分类头前的池化特征，按训练库标准化并以余弦近邻投票。k=21 时，原图、q75、中等和强退化四个库分别对测试投出 **16.6%、21.5%、27.5%、28.7%** 的生成票。对应有标签验证准确率依次为 **91.94%、92.94%、74.88%、69.00%**。原图 kNN 的独立最近邻余弦距离中位数由验证的 0.076 升至测试的 0.124。k=5 的测试票率最高为 32.6%。当通过退化拉近某些邻域，投票比例随之变化，验证也同步退化。这些投票可指出与旧提交有分歧的图，类别先验仍需真值或可靠校准域支持。

用原图和五档有标签代理的两类分数直方图拟合测试分数，估计的生成占比约 **0–21%**，落在上述 31–57% 界限之外。条件参数 bootstrap 对所有档位给出 `p < .05`，总变差距离约 0.059–0.200。检验以各代理直方图固定为条件，描述的是这些代理对测试分数形状的失配。仅改变类别比例无法修复这些条件分布。

## 配对代理与模型重排

每档使用固定的 1,600 个验证 ID。先处理整图，再走 checkpoint 自己的模型输入几何与归一化。缩放使用 bicubic，JPEG 使用 4:2:0。

| 评测版本 | 整图处理 | 旧 0.560 提交对应 checkpoint 的 acc / AUROC | 真 / 生成召回 |
| --- | --- | ---: | ---: |
| 原图 | 原编码解码 | 92.31% / .9750 | 93.25% / 91.38% |
| q75 | 原尺寸 q75 | 91.50% / .9782 | 96.38% / 86.63% |
| scale75 | 缩至 0.75 倍 | 72.94% / .8499 | 87.00% / 58.88% |
| scale75 + q75 | 缩至 0.75 倍再 q75 | 73.63% / .8699 | 94.00% / 53.25% |
| 中等 | 随机 0.75–1.0 倍，q73–95 | 67.81% / .7463 | 92.00% / 43.63% |
| 强 | 随机 0.5–0.75 倍，q60–80，模糊半径从 0、0.45、0.8 取值 | 63.94% / .7096 | 92.75% / 35.13% |

只缩放就比原图低 **19.38 个百分点**；相同 q75 下加入固定缩放低 **17.88 个百分点**，生成召回低 **33.38 个百分点**。加压缩在这个固定缩放对照中略抬高总准确率，生成召回则进一步下降，说明两种处理存在交互，不能把分数差统一归给某个 JPEG 质量。旧训练中的 JPEG 增强在裁剪后执行，测试输入的编码和重采样痕迹则在裁剪前就已形成。

按类别分层对同一批 ID 作 2,000 次配对 bootstrap，只缩放的准确率变化为 **−19.38 个百分点**（95% 区间 −21.56 至 −17.19）。相同 q75 下加入固定缩放为 **−17.88 个百分点**（−19.88 至 −15.69）。原始 **256×256** 的 297 张生成图，q75 代理召回 **100.00%**，加入缩放后仅 **12.46%**。原始 **512×512** 的 301 张则由 **80.07%** 到 **83.39%**。受影响的主要是一部分原始分辨率的生成图，结果与模型依赖重采样及纹理尺度线索相符。

重评覆盖七个代表性旧 checkpoint，包括原图最强、原提交、两种全 JPEG 增强、不同输入大小和无 CAP 对照。下表统一采用 0.5 概率阈值，五档最差和均值只计退化代理。完整 AUROC、召回和留出指标见[冻结模型分析](runs/audit_shift_20261121/frozen_analysis/analysis.json)。

| 冻结 checkpoint | 原图 acc | q75 | 仅缩放 | 缩放 + q75 | 中等 | 强 | 五档最差 / 均值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `w8_fix75_352` | 83.62% | 80.31% | 74.62% | 68.19% | 70.81% | 66.25% | 66.25% / 72.04% |
| `w7_cap_jpeg10` | 86.56% | 86.56% | 69.62% | 70.06% | 77.38% | 65.94% | 65.94% / 73.91% |
| `w3_native320_long` | 86.75% | 85.44% | 73.00% | 72.06% | 74.00% | 64.75% | 64.75% / 73.85% |
| `w6_cap60_jpegaug` | 92.31% | 91.50% | 72.94% | 73.62% | 67.81% | 63.94% | 63.94% / 73.96% |
| `w8_fix75_320` | 84.12% | 80.56% | 64.81% | 61.69% | 74.12% | 64.06% | 61.69% / 69.05% |
| `w7_nocap_jpeg10` | 82.19% | 82.19% | 70.94% | 71.38% | 77.00% | 59.62% | 59.62% / 72.23% |
| `w5_cap60` | 94.38% | 77.56% | 72.94% | 56.56% | 56.38% | 57.25% | 56.38% / 64.14% |

以固定的 800 张类平衡校准半集，先最大化五档代理的最差准确率，再比均值。阈值在 logit 差 `[-2, 2]` 上按 0.05 扫描，最差档至少改善 0.5 个百分点才偏离默认阈值。剩余 800 张只用于审核本轮阈值与重排。旧 checkpoint 历史上可能已看过这些验证 ID，因此这是本轮校准的留出检验。

旧权重中校准半集选到 `w8_fix75_352`，阈值约 0.525，五档最差 68.63%、均值 72.93%，留出半集最差 65.00%。同一规则校准旧提交 checkpoint，在留出半集最差 65.63%。重排的微小优势对验证抽样不稳，因此保留整表并用新修复试验作下一步比较。

在该留出半集上，逐档重抽成 34%、40%、50%、57% 四种生成先验。强制 40% 的 20 项平均准确率变化范围为 **−4.00 至 +4.54 个百分点**，强制 50% 为 **−3.56 至 +1.84 个百分点**。测试先验未识别，先验匹配会依赖额外假设。测试 logit 的 KDE 在 Scott 带宽倍数 0.6、1.0、1.4 下均只有一个达到 2% 峰显著度的峰，概率约 3.1–3.4%。1、2、3 成分高斯混合的 BIC 分别为 4017、3609、3572，可用多成分描述偏态分数，成分权重不代表真实类别比例。

### 宽 500 定向对照

对同一批验证图的两类等比变宽至 500 后，以实测两张量化表和 4:2:0 重编码，再做原模型裁剪。该对照在发现处理分组后增加，独立于五档主排名。

这里同时改变了宽度和量化表，并保持原始长宽比，衡量的是两项处理组合对当前验证来源的影响。测试批次的逐图类别与图像来源仍未知。见[复现脚本](audit_width500.py)和[原始指标](runs/audit_images_20261121/width500_metrics.json)。

### Kaggle 对照候选

[submission.csv](submissions/submission.csv) 来自 `w8_fix75_352` 原样测试图的像素推理。阈值约 0.525，由代理校准半集选出。文件有 1,000 行，按模板顺序，340 张判为生成。与旧提交的 276 行变化中，243 行从真实改为生成，33 行从生成改为真实。选择它做一次对照的新增证据是宽 500 代理提高 **14.38 个百分点**，五档代理中的改善不一致。用户实际提交后回报 **0.53800**，比旧提交 **0.560** 低 **2.20 个百分点**。报告沿用交接的全量 Accuracy 定义，页面的 Public/Private 范围尚待确认。宽 500 代理提升未迁移到比赛分数，说明单档定向代理不宜独立用来选提交。

如两份成绩均为同一批全量 1,000 张的 Accuracy，276 个变化中有 **127** 行新版正确、**149** 行旧版正确。由预测交叉计数可约束 243 张新增生成预测中真正的生成图数为 **94–127**，即精确率约 **38.68%–52.26%**。因此把预测生成比例从 13% 拉到 34% 未改善此次得分。若页面只显示 Public 子集成绩，这些代数结论还需要该子集上的预测交叉计数。

## 域增强修复试验

EfficientViM-M1 无 CAP，种子 42，随机初始化并训练 15 轮（1,500 次优化更新），A800 单卡训练 22.84 分钟。两类在裁剪前一律重编码为随机 q60–95 的 4:2:0 JPEG，75% 的样本先缩放到 0.5–1.0 倍，30% 施加轻微高斯模糊。用固定缩放和两档随机代理中的最低准确率选择第 15 轮。随后换一套独立的退化随机种子，用同一批验证 ID 按统一协议重评。随机绘制的代理仍共享原验证图和来源。

| 版本 | 旧提交 checkpoint acc / AUROC | 修复版 acc / AUROC | 修复版真 / 生成召回 |
| --- | ---: | ---: | ---: |
| 原图 | 92.31% / 0.9750 | 72.88% / 0.8154 | 83.62% / 62.12% |
| q75 | 91.50% / 0.9782 | 72.81% / 0.8197 | 82.88% / 62.75% |
| 仅缩放 | 72.94% / 0.8499 | 73.81% / 0.8157 | 81.00% / 66.62% |
| 缩放 + q75 | 73.62% / 0.8699 | 73.69% / 0.8146 | 80.00% / 67.38% |
| 中等 | 67.81% / 0.7463 | 74.44% / 0.8205 | 82.75% / 66.12% |
| 强 | 63.94% / 0.7096 | 70.62% / 0.7879 | 71.00% / 70.25% |

五档统一代理下，最差准确率从 **63.94%** 变为 **70.62%**，均值从 **73.96%** 变为 **73.08%**。修复版本轮校准留出半集最差 70.88%。八模型统一校准规则选到 `audit_repair_nocap_20261121`，其留出半集最差 70.88%。修复组同时改动训练预算、CAP 和增强，需等预算消融才能量化各项贡献。0.538 已表明代理优势不保证比赛收益，本轮比赛对照仍以已提交的文件为准。

[修复模型候选 CSV](submissions/submission_domain_repair.csv) 按模板导出 1,000 行，代理校准阈值 0.574，其中 222 张判为生成。此版本尚无比赛评分。

原始结果见[修复训练结果](runs/tune/audit_repair_nocap_20261121/results.json)和[八模型统一分析](runs/audit_shift_20261121/combined_analysis/analysis.json)。


## 后续实验

1. **让训练管线覆盖缩放、模糊和重编码的顺序。** 两类都在裁剪前整图采样退化参数并重编码。以最差跨域代理准确率选 checkpoint，同时报告代理均值、生成召回和原图参考。统一重编码会保留真实图已有的压缩历史，因此仍需保留多个几何档位。另做同预算的 CAP 开关对照，量化先验是否仍有跨域收益。
2. **固定协议和预留评估。** 在训练前固定退化范围及随机种子，并预留模型选择用不到的原图 ID 用于最终代理评估。多个代理同时评估不同几何，补一组同源/跨来源划分的条件是拿到生成器或来源标注。
3. **核实测试构建。** 向主办方询问两种宽度及量化表批次是怎样构成的、是否与标签相关，以及 0.560 是否在全量 1,000 张上计算。研究 A/C 两条路线的原图与代理降幅可用于说明模型对处理链的敏感性。没有测试真值时逐图错误原因仍未确定。
4. **节省提交次数。** 本轮已用一份像素候选做线上对照，得到 0.538。先核实测试批次与评分范围，再评估下一次提交是否有足够新信息。取反版由指标定义可直接计算，先验匹配版需要可信比例或跨代理的一致收益。
