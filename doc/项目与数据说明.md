# AI 生成图像识别 · 小组项目与数据说明

本项目按图像来源做二分类，真实图像记为 `0`，AI 生成图像记为 `1`。模型从随机权重开始训练，最终按比赛模板为每张测试图提交预测。小组继续使用原 GitHub 仓库，当前选题以本文为准。[Kaggle 比赛主页](https://www.kaggle.com/competitions/ai-generated-image-detection-benchmark)

## 获取数据并核对目录

从比赛入口获取标签、提交模板及其配套图像包。本组使用的两个压缩包分别为 `ai-generated-image-detection-benchmark.zip` 和 `dataset.zip`。按以下层级解压到仓库根目录，即可复用相同的相对路径。[比赛数据页](https://www.kaggle.com/competitions/ai-generated-image-detection-benchmark/data)

```text
ai-generated-image-detection-benchmark/
  train_labels.csv
  sample_submission.csv
dataset/
  dataset/
    train/
      0_real/
      1_fake/
    test/
```

| 文件 | 内容与用法 |
|---|---|
| `train_labels.csv` | 8000 行，列为 `image_id,label,image_path`。真实与生成图各 4000 张。 |
| `sample_submission.csv` | 1000 行，列为 `image_id,label`。保留模板的 ID 和顺序，用预测结果填入 label；模板中的 0 是占位值。 |
| `dataset/dataset/test/` | 1000 张测试图，与模板 ID 一一对应，仅用于最终推理。 |

CSV 中的路径已包含内层 `dataset/`。从仓库根目录运行时，用 `Path("dataset") / row["image_path"]` 定位训练图。例如首行对应 `dataset/dataset/train/0_real/real-0001.jpeg`。本组已逐张解码 9000 张图，核对标签与图像路径，未发现字节完全相同的重复图片。

## 数据特征与验证实验

训练集中，4000 张真实图全部采用 JPEG 编码，4000 张生成图全部采用 PNG 编码。另有 3502 张生成图集中在 128、256、512 像素三种正方形尺寸。按类别随机划分后，这些特征会同时出现在训练和验证集中。模型即使只接收像素，也可能借助压缩痕迹识别来源。

1. **固定划分。** 使用[固定划分清单](../splits/train_val.csv)，每类 800 张验证图、3200 张训练图。对每类按 UTF-8 字符串 `42:<image_id>` 的 SHA-256 升序排列，取前 800 张标记为 `val`，其余标记为 `train`。清单保留原标签 CSV 的列和行序，并追加 `split` 列。若发现同图变体，将同组样本放入同一划分。由训练子集估计归一化参数，测试图不参与训练、选模或调参。
2. **建立基线。** 采用随机初始化的 ResNet-18（`weights=None`），输入统一转换为 RGB，采用相同的空间预处理。模型只接收图像像素；路径、文件名和扩展名只用于加载。记录验证准确率、两类召回率和混淆矩阵。
3. **检验压缩影响。** 为同一批验证图生成统一 JPEG 质量的副本，比较原图和重编码图上的表现。再训练一组对两类等概率施加 JPEG 增强的模型，保持划分、训练预算和其他设置一致。重编码会引入新的压缩痕迹，已有 JPEG 的压缩历史仍然存在，因此该实验衡量的是模型对再次压缩的敏感程度。
4. **按模板推理。** 模型与配置确定后加载本组最佳 checkpoint，按模板顺序预测。导出前核对列名、行数、ID 唯一性及完整覆盖，并按比赛 Evaluation 页确认提交值要求。

## 环境与开训检查

本机已验证 Python 3.12.7、PyTorch 2.6.0+cu124 和 RTX 4060 Laptop（8 GB）可执行 CUDA 张量运算。组员在各自环境中安装匹配的 PyTorch 与 torchvision，记录实际版本。先用一个训练批次完成前向、反向和参数更新，再跑一轮验证，并重新加载 checkpoint 复现预测。
