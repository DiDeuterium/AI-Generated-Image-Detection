# 航拍地表覆盖分割 · 小组开发指南

本项目从随机权重训练语义分割模型，为航拍图的每个像素预测地表类别。小组在 GitHub 共享代码、实验配置、数据划分和训练记录。比赛原始文件由各成员从 Kaggle 下载到本地。当前已核验官方数据包，下一步是取得带掩码的训练样本和独立验证样本。[小组仓库](https://github.com/DiDeuterium/Ground-Cover-Segmentation) · [比赛数据下载](https://www.kaggle.com/competitions/ground-cover-segmentation-challenge-by-duality-ai-lunate-ai/data)

## 本地目录与数据用途

克隆仓库后，将下载包解压到仓库根目录的 `ground-cover-segmentation-challenge-by-duality-ai-lunate-ai/`。Git 已忽略该目录。下表中的路径均相对于这个解压目录。

| 路径 | 已核验内容 | 用途 |
|---|---|---|
| `Allowed_in_the_VAL_folder_ONLY/Allowed_in_the_VAL_folder_ONLY/` | 100 张 RGB PNG，无配套掩码 | 仅限验证。有标签前可单独展示预测，计算 Dice 需要对应真值。 |
| `archive/testing_images/Color_Images/` | 946 张 RGB PNG，无配套掩码 | 最终推理。课程禁止以测试图训练、调参或估计归一化参数。 |
| `archive/train_segmentation.py` | 训练示例，包含数据读取、标签转换和模型定义 | 参考文件组织和标签处理，课程模型需从零训练。 |
| `archive/test_segmentation.py` | 推理及提交示例 | 参考类别顺序、原图尺寸恢复和 CSV 编码。 |
| `archive/ENV_SETUP/ENV_SETUP/` | 3 个 Windows 批处理脚本 | 查阅示例环境的依赖。 |

2026 年 11 月 19 日核验结果为 1051 个文件，其中 PNG 1046 个、Python 脚本 2 个、批处理脚本 3 个，与 Kaggle Data Explorer 一致。所有 PNG 均已完整解码。图像尺寸有多种，包括 500 × 500 和 501 × 500。两个图像目录之间没有相同文件名或相同 SHA-256 的文件。

## 获取训练数据并确定标签

1. 先核对课程平台是否另发带标注的数据包。若采用比赛的 Falcon 合成数据路线，先从一个场景导出一批 RGB 图、原始分割掩码和对象 ID 说明，保存场景标识。确认配对和映射后，再扩充场景与样本。[比赛说明](https://www.kaggle.com/competitions/ground-cover-segmentation-challenge-by-duality-ai-lunate-ai/overview)
2. 训练示例在每个数据划分下读取 `Color_Images/<样本名>.png` 和 `Segmentation/<同名文件>.png`；其默认路径指向作者电脑。小组代码应从配置读取数据根目录，划分清单使用相对路径。先按独立场景、航线或原图划分训练与验证，再对各自图像裁块。各组实验复用同一份划分。
3. 推理示例约定输出类别为 **0 其他、1 建筑、2 水体、3 树木**。这些编号与模拟器原始对象 ID 是两套编码。训练示例的 `value_map` 将注释为 water 的 `1100` 映射到 `0`，却把注释为不透水面的 `2` 映射到水体编号 `2`。应依据实际导出配置和带已知水面的样本确认原始 ID，保存经核对的映射表。读取原始掩码时保留原位深，避免大于 255 的 ID 被截断；遇到未知值应列出并核实，示例代码会将其默认为其他。
4. 逐对检查文件名、尺寸、图像与标签的空间对齐。对水面、屋顶和树冠各画几张叠加图。统计各类像素占比和含该类的图块比例，再决定是否采用稀有类采样。几何增强应同步作用于图像与掩码，掩码缩放采用最近邻插值。

## 环境与第一次训练

本机已验证 Windows、Python 3.12.7、PyTorch 2.6.0+cu124 和 RTX 4060 Laptop（8 GB）能完成 CUDA 张量运算。官方批处理使用名为 EDU 的 Conda 环境和 CUDA 11.8 构建。组员可在独立环境中安装适合本机的 PyTorch，并记录实际使用的 Python、PyTorch、torchvision 和图像处理库版本。[PyTorch 安装说明](https://pytorch.org/get-started/locally/)

```powershell
python -c "import torch; print(torch.__version__, torch.version.cuda); print(torch.ones(1, device='cuda'))"
```

- **模型初始化。** 官方训练和推理示例均通过 `torch.hub.load` 加载 DINOv2。课程禁止使用预训练模型。建议以随机初始化的 U-Net 建立基线，推理时加载本组训练得到的 checkpoint。
- **小样本试跑。** 用 4–8 张已配对的训练图块关闭随机增强，运行前向、反向和参数更新。检查 loss 下降以及预测与真值的重合情况。8 GB 显存可先用 512 × 512 图块、batch size 2 和混合精度试测，再按实测显存调整。
- **验证与提交。** 在带真值的固定验证集上累计四类的 TP、FP、FN，分别计算 Dice 并报告宏平均，统一忽略像素及空类处理。合成验证结果应标明数据来源。最终预测恢复到各张输入图的原始尺寸；官方脚本按行展开掩码，以从 1 开始的游程编码生成 CSV，每图四行，字段为 `id`、`class`、`predicted`。
- **复现与交付。** 每次实验保存提交号、数据版本、划分清单、随机种子、训练配置、逐轮训练与验证日志以及最佳 checkpoint。正式长训练前先跑完一个短周期，重新加载 checkpoint 并复现一张验证图的预测。小组提交代码、checkpoint（可附外部链接）、训练日志和 CVPR 2027 双栏报告 PDF，正文不超过 8 页。
